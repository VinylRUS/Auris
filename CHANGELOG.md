# Changelog

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версионирование — [SemVer](https://semver.org/lang/ru/).

## [0.0.1f] — музыка наконец воспроизводится

Фокус релиза: **воспроизведение**. Данные после 0.0.1e подтягиваются,
но любой трек при нажатии падал с сетевой ошибкой — очередь молчала,
«Моя волна» запускалась и тут же замолкала.

### Исправлено

- **Музыка не воспроизводилась** (критично): `/tracks/{id}/download-info`
  отдаёт ссылку на XML-метаданные в поле `downloadInfoUrl`, а модель
  `DownloadInfo` ждала `url`. serde молча подставлял пустую строку, и
  reqwest падал с малопонятным
  `builder error: relative URL without a base` — вместо трека тишина.
  Поле переименовано по живой форме API (сверено с эталоном
  MarshalX/yandex-music-api), фикстура `download_info.json` переписана
  с живым именем поля (старая писалась по памяти — из-за этого golden-
  тест горел зелёным на сломанной модели).
- **Защита от повторения**: пустой/относительный URL теперь
  отлавливается до запроса с внятным сообщением
  («download-info вернул непригодный URL…»), а не текстом ошибки
  reqwest; добавлены юнит-тесты на живую форму ответа и на
  регрессию с неверным именем поля.
- **400 «invalid uid: 0» на главной до завершения входа**: главная
  грузилась до готовности аккаунта и звала
  `users_playlists_list(0)`. Теперь при неизвестном uid лента
  показывается без персональных списков и лайков (с предупреждением
  в лог), а не падает целиком.

### Затронуто

- `auris-api`: `models/download.rs` (поле + тесты), `sign.rs`
  (валидация URL + тест), фикстура и golden-тест.
- `auris`: `playback.rs` — новое имя поля; `app.rs` — guard uid.
- `auris-core`: `downloads.rs` — новое имя поля (скачивание треков
  чинится тем же изменением).

## [0.0.1e] — данные наконец подтягиваются

Фокус релиза: **данные из Яндекса**. Вход чинить научились (0.0.1d),
но лента, плейлисты, лайки, радио и поиск оставались пустыми —
приложение молча не понимало ответы API.

### Исправлено

- **Все данные приходили пустыми** (критично): API заворачивает
  любой ответ в `{"result": …, "invocationInfo": …}`, а клиент
  разбирал внешний конверт как полезную нагрузку. serde молча
  подставлял дефолты: аккаунт — «Слушатель», лента — пустая,
  uid — 0. Теперь обёртка разворачивается (как в эталонной
  библиотеке сообщества MarshalX/yandex-music-api).
- **`permissions.default` падал на гостевой форме**: живой API
  отдаёт права то строками, то объектами — десериализатор
  принимает обе формы (найдено живым тестом против api.music.yandex.net).
- **Плейлисты ленты**: в `/feed` плейлист лежит в поле `data`,
  а не `playlist` — «Собрано для вас» снова собирается.
- **Радио**: станции дашборда лежат в корне ответа (не в обёртке
  `dashboard`), а сид станции — внутри `station.id`, а не рядом.
- **Лайки**: `/users/{uid}/likes/tracks` отдаёт укороченные записи
  `{id, albumId}` — теперь идентификаторы догружаются полными
  карточками через `/tracks` (батчами по 100, чтобы URL не разрастался).
- **Чипы «Новинки»/«Чарт»**: `landing3/new-releases` отдаёт только
  id альбомов (карточки догружаются), `landing3/chart` — плейлист
  чарта в поле `chart`.
- **Паника на кириллице в ошибках**: тела ошибок урезались байтовым
  срезом `&text[..512]` — на границе UTF-8 символа это падение
  задачи; теперь усечение по границе символов, а из тела ошибки
  достаётся человекочитаемое `error.name: error.message`.

### Добавлено

- **Ошибки загрузки видны в UI**: если главная не загрузилась,
  под приветствием появляется баннер с причиной — вместо молча
  пустой страницы (и в журнале, как раньше).
- **Лёгкая загрузка главной**: лайки для счётчика и сердечек
  берутся одним запросом без догрузки полных карточек и обложек.

## [0.0.1d] — предрелизная сборка

Фокус релиза: **рабочий вход** и **данные рядом с программой**.

### Исправлено

- **Вход не работал ни у кого** (`invalid_client`): в `client_secret`
  была опечатка — одна буква. Яндекс на любой запрос отвечал
  «Wrong client secret». Значение сверено с MarshalX/yandex-music-api
  и покрыто регресс-тестом; ошибки OAuth теперь показывают описание
  от сервера, а не голый код.
- **Экран подтверждения живёт всё время действия кода** (5 минут):
  обратный отсчёт, опрос каждые 5 с, устойчивость к минутным сетевым
  заминкам, обработка `slow_down`/`expired_token`/`access_denied`
  по RFC 8628 (доделано в 0.0.1c-hotfix, здесь стабилизировано).

### Добавлено

- **Портативные данные**: журнал, настройки, токен, кеш и загрузки
  обновлений лежат в папке установки (`logs/`, `config/`, `data/`,
  `cache/`, `updates/`) — на системный диск не пишем. Если папка
  установки доступна только для чтения, используется каталог
  данных ОС; старые файлы переносятся автоматически.
- **Журнал**: `logs/auris.log` с ротацией (2 МБ × 3 поколения),
  локальное время, heartbeat OAuth-опроса и ошибки сети — на уровне
  `info`; подробная диагностика — `AURIS_LOG=debug`.

## [0.0.1c] — предрелизная сборка

Фокус релиза: «подключаем всё, что можно подключить» — ранее добавленные,
но не задействованные в интерфейсе методы API теперь работают в UI.

### Исправлено

- **Сайдбар больше не уходит под панель воспроизведения**: разделы
  «Настройки» и карточка профиля перекрывались плавающим плеером —
  сайдбар теперь заканчивается выше плеера, как в Яндекс.Музыке.

### Добавлено

- **Тексты песен**: панель лирики (кнопка в плеере), автозагрузка
  `GET /tracks/{id}/supplement`, кеш по треку, аккуратная типографика
  построчно, состояния «загрузка»/«текст не найден».
- **Альбомы**: плитки новинок открывают альбом (`GET /albums/{id}/with-tracks`)
  с обложками; лучший результат поиска типа «альбом» тоже открывается.
- **Исполнители**: открытие карточки исполнителя
  (`GET /artists/{id}/brief-info`) с популярными треками — из поиска
  и библиотеки.
- **Библиотека**: секции «Альбомы» и «Исполнители» из лайков
  (`GET /users/{uid}/likes/albums`, `.../likes/artists`).
- **Радио**: станции из дашборда ротатора (`GET /rotor/stations/dashboard`)
  с фолбэком на встроенные жанры/настроения.
- **Подсказки поиска**: живые саджесты при вводе
  (`GET /search/suggest`) с дебаунсом 350 мс и выпадающим списком.

### Изменено

- Версия: `0.0.1-beta.1` → `0.0.1-beta.2` (отображается как `0.0.1c`).

## [0.0.1b] — 2026-10-27

Первый релиз с установщиком и автообновлением. Device Flow проверен на живом API.

### Добавлено

- **Установщик Windows** (Inno Setup): установка per-user в `%LOCALAPPDATA%\Auris`
  без прав администратора, ярлыки, деинсталлятор, русский/английский мастер;
  при обновлении запущенное приложение закрывается автоматически.
- **Автообновление**: тихая проверка GitHub Releases при запуске и по кнопке
  в настройках; скачивание установщика с прогрессом и отменой, проверка
  SHA-256, запуск установщика и перезапуск (Windows); на Linux/macOS —
  переход на страницу релиза. Канал — `latest.json` в «последнем» релизе.
- **Иконка приложения** (Fluent-стиль, эквалайзер) + метаданные версии
  в `auris.exe` (FileVersion/ProductVersion через winresource).
- Карточка «Обновление» в настройках: статус, примечания к версии,
  прогресс-бар, отмена, повтор при ошибке.
- CI: релизный пайплайн собирает установщик на Windows-раннере, публикует
  `Auris-Setup-<версия>-x64.exe`, портативные архивы, `latest.json`
  и `SHA256SUMS.txt`.
- **Полный редизайн интерфейса**: 34 векторные SVG-иконки Fluent-стиля
  (тонировка `colorize`, чёткость на любом DPI) вместо текстовых unicode-глифов;
  кнопки окна в стиле Win11 (крест с красным наведением); анимированный
  эквалайзер у играющего трека; hover-состояния и плавные переходы у всех
  контролов; кнопка play на плитках при наведении; проявляющиеся действия
  в строках треков; громкость с mute по клику; тень у плавающего плеера;
  «дышащие» волны на главной и волне; демо-режим UI (`AURIS_UI_DEMO=1`)
  для скриншот-тестирования.

### Изменено

- Версия: `0.0.1-alpha.1` → `0.0.1-beta.1` (отображается как `0.0.1b`).
- Вёрстка страниц: фикс «разъехавшихся» пустот — всем Flickable задано
  `alignment: start` и честные `content-height`.

## [0.0.1a] — 2026-10-27

Самая ранняя альфа. Каркас приложения целиком, без обкатки на живом API.

### Добавлено

- **auris-api**: клиент API Яндекс.Музыки — OAuth Device Flow, статус аккаунта,
  лента, поиск, плейлисты, лайки, варианты загрузки с вычислением прямых ссылок
  (`md5(SALT + path + s)`), Rotor Session API («Моя волна», станции, фидбек);
  golden-тесты на зафиксированных ответах.
- **auris-player**: плеер-сервис на rodio + symphonia (play/pause/seek/volume),
  события окончания дорожки, снапшот состояния для UI.
- **auris-core**: конфиг (JSON), хранилище токена (keyring + файловый fallback),
  кеш обложек и аудио, менеджер загрузок с прогрессом, локальная история.
- **auris**: Slint UI — экран входа (QR + код + резервный токен), главная,
  поиск, библиотека, «Моя волна», радио, скачанное, настройки; плеер-бар,
  очередь, кастомный титлбар без нативных декораций.
- Темы: Fluent Dark/Light, тёплая пастель, мятная пастель, монохром Dark/Light
  + пользовательский акцентный цвет с автоконтрастом текста.
- Медиа-контролы ОС (SMTC/MPRIS) через playwire, фича `media-controls`.
- CI: проверка сборки на Ubuntu/Windows/macOS, тесты API-крейта.
